# WIND-UP WINGS!（ワインドアップ・ウィングス）

ゼンマイ3人組の 大空大作戦！ ― 1930年代カートゥーン風の縦スクロールシューティング。
画像ファイルなし：キャラ・敵・背景はすべてCanvasで描画、音はWeb Audioで合成。

## 開発

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

## フォルダ構成

| 場所 | 中身 |
|---|---|
| `src/main.ts` | 入り口。保存データ復元 → 言語 → ゲーム起動 → アプリ連携 |
| `src/game/` | ゲーム本体（1ファイル版から機械的に分割したJS） |
| `src/game/state.js` | ファイルをまたいで書き換える共有状態 `GS`（自機 `GS.P`、進行 `GS.G` など） |
| `src/game/foreground.js` | 前景レイヤー（ステージごとの手前の景色） |
| `src/game/i18n-bind.js` | ステージ名・ボス名・強化カードなどの表示名を辞書から読むようにする |
| `src/i18n/strings.ts` | 日本語・英語の文言（正本） |
| `src/platform/` | 保存データ（Web＋端末保存の二重化）、iOS/Android連携 |
| `ios/`、`android/` | Capacitor のネイティブプロジェクト |
| `legacy/` | 元の1ファイル版（比較用） |

## 挙動が変わっていないことの確認

元の1ファイル版と今のコードを、同じ乱数・同じ時間・同じ入力で動かし、ゲーム状態を毎フレーム比べる。

```bash
node scripts/parity-check.mjs 20000 3
```

引数は「フレーム数」「乱数シード」「`inv`（無敵にして先へ進める）」「開始ステージ」の順。
前景は専用の乱数で動くので、前景を足しても敵の出方・難易度は元の版と同じ。
ゲームの調整値を意図して変えたときは、このチェックが不一致になるのが正しい。

確認用スクリーンショット：

```bash
node scripts/screenshots.mjs screenshots
```

## ゲームのルール（守ること）

- 既存作品のキャラ・絵・UIをまねしない。追尾弾は入れない
- 敵の体力ゲージはしっかり見せる（前景もゲージや弾を隠さない位置・順番で描く）
- ボスは通常弾だけにせず、ビーム・ミサイル・必殺技で変化をつける。ステージごとにテンションを変える
- 主人公は目つき悪め（ロボだけかわいい目）。サメは尾びれを揺らすだけ
